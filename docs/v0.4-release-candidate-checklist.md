# nScout v0.4.0 — Release Candidate Gates

Status: **preparation only; no stable v0.4.0 release authorized or published**.

## Release scope
- Windows-first Tauri 2 desktop application with bundled FastAPI sidecar.
- **Npcap remains required** for supported Windows live packet capture. PCAP imports and offline investigations must work without live capture permissions.
- Linux AppImage/deb and macOS app/DMG are development artifacts, **not production-supported** until separately validated on clean systems.
- Native Pktmon/WFP live-capture replacement, Full AI Analyst, Sensor Mode and threat-intelligence providers are deferred. Do not represent experimental prototypes as supported backends.
- Preserve existing v0.3 stable release and browser/developer mode.

## Hard blockers — all must pass before stable publication
- [ ] Latest branch head passes focused backend tests, complete frontend tests/build, Docker workflow and desktop development workflow on Windows, Linux and macOS.
- [ ] Review the final code diff against v0.3, dependency licenses, third-party notices, bundled binary dependencies, security defaults, privacy redaction and release claims.
- [ ] Install Windows NSIS development artifact on a **clean Windows machine/VM**; verify launch without a console/browser, readiness timeout/error messages, loopback-only backend and single-instance focus.
- [ ] Verify close/relaunch, forced termination, orphan cleanup, sleep/resume, Windows shortcut, upgrade from a previous test build, and uninstall; confirm no unintended user-data deletion.
- [ ] Test live interface enumeration and real capture with Npcap; verify permission failure, interface switching, packet retention, pause/stop and diagnostics. Do not silently substitute simulated traffic on live failure.
- [ ] Import known benign PCAP/PCAPNG, inspect packets/flows/DNS/TLS, and verify search, host focus, timeline, comparison and baseline behavior.
- [ ] Complete an investigation: create case, bookmark packet/host/flow/finding evidence, add note, update finding state, close/restart/reopen case, verify durable persistence, remove evidence, and generate PDF/HTML/JSON/CSV/XLSX/XML reports with redaction on/off.
- [ ] Exercise empty/error states, malformed/oversized PCAPs, unavailable capture backend, read-only or corrupt local storage, and failed report generation without data loss.
- [ ] Validate responsive navigation, tables, drawers and dialogs at narrow, normal, maximized and ultrawide viewport sizes; ensure no inaccessible controls or clipping.
- [ ] Verify final Windows installer SHA-256 against the CI-produced SHA256SUMS.txt; record the exact tested commit and artifact.
- [ ] Prepare accurate installation instructions, known limitations, changelog, security/privacy caveats, attribution and release notes.
- [ ] Obtain explicit approval before merging, creating a stable tag, attaching release binaries or publishing.

## Build/release safety
- The existing `.github/workflows/build.yml` is the **legacy browser-launcher** pipeline and publishes assets for `v*` tags. Never create `v0.4.0` or `v0.4.0-rc*` tags until that workflow is reviewed/guarded; otherwise it may publish the wrong installer.
- Use `.github/workflows/desktop-development.yml` for development Tauri packages. Its Windows artifact includes a SHA-256 manifest; build success is **not** clean-system runtime validation.
- The release candidate must be tested as an immutable commit/artifact pair. Record test evidence, failures and retests; never check a box based only on packaging success.
