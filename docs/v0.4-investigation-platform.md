# nScout v0.4.0 — Investigation Platform

v0.4 turns the v0.3 security-intelligence foundation into a persistent analyst workflow. Full AI Analyst remains deferred to v0.5; threat-intelligence providers and Sensor Mode remain later milestones.

## Delivery tracks

### Capture and workspace
- Seamless capture-interface switching with optional packet preservation
- Named capture sessions and investigation sessions
- Packet retention / buffer controls
- Workspace persistence and crash recovery
- Capture health and diagnostics
- Better empty and error states
- Keyboard shortcuts

### Investigation
- Bookmarks and analyst notes
- Evidence locker
- Finding lifecycle: New → Investigating → Benign/Suspicious/Confirmed → Resolved
- Global investigation search
- PCAP comparison
- Explainable network baselines and anomaly detection
- Detection presets and rule controls

### Host investigation
- Dedicated Live Hosts workspace using observed/recently-seen semantics
- Host aliases and identification
- First/last-seen activity history
- Host watchlist
- Host-focused packets, connections, DNS, findings and timeline

### Intelligence and visualization
- TLS metadata/correlation improvements without claiming HTTPS decryption
- Network Map 2.0 with host focus, filtering and connection drill-down
- Fix Network Map search-input icon/placeholder overlap
- Sticky Advanced Packet Search controls

### Reports and privacy
- Investigation Report as a first-class navigation/workspace action
- PDF, HTML, JSON, CSV, XLSX and XML exports
- Reporting 2.0 with evidence, notes, findings, hosts and timeline context
- Optional privacy redaction for shareable reports

### Application settings and profiles
- AI integration master switch, OFF by default
- Expanded capture, investigation, privacy, detection and alert settings
- Local nScout profiles (no cloud account requirement)

## Engineering rules
- Develop on `v0.4-investigation-platform`, not directly on `main`.
- Keep changes reviewable and regression-tested.
- Do not expose inactive AI controls when AI integration is disabled.
- Treat a host as Active/Recently Seen/Inactive based on observation timestamps; passive capture cannot prove that a silent host is offline.
- Never describe TLS metadata inspection as encrypted payload decryption.
- Preserve v0.3 behavior unless a v0.4 change intentionally replaces it.
